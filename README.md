# 얼마면 가? — 스냅샷 버전

기존 사이트(상위 폴더)와 별개인 새 버전입니다. 방문자마다 실시간 조회하지 않고, 주 1회 수집한 가격 파일 하나로 화면을 보여줍니다. 서버와 DB가 없고 `site/` 폴더만 정적 호스팅에 올리면 됩니다.

이 폴더는 `.git/info/exclude`로 기존 저장소의 커밋 대상에서 빠져 있습니다.

## 구성

- `collect.mjs` — 가격 수집 스크립트. 결과를 `site/data/snapshot.json`에 저장합니다.
- `lib/quotes.mjs`, `lib/stays.mjs` — 기존 사이트 `server/`의 응답 검증·정규화 코드 사본(수정 없음).
- `lib/config.mjs` — 수집할 도시, 일정 패턴, 도시별 현지 경비 추정 단가.
- `lib/mock-provider.mjs` — 가상 응답. 실제 가격이 아닙니다.
- `site/` — 화면(HTML·CSS·JS)과 가격 파일.
- `test/` — 자동 검사.

## 명령

```bash
node collect.mjs          # 조회 계획만 출력, 외부 호출 0회
node collect.mjs --mock   # 가상 데이터로 스냅샷 생성, 외부 호출 0회
node collect.mjs --live   # 실제 SerpApi 조회 (유료 한도 사용)
node --test test/*.test.mjs   # 자동 검사
node serve.mjs            # http://localhost:5273 미리보기
```

`--live` 옵션: `--max-calls N`(기본 160) · `--cities fukuoka,osaka` · `--seller-quote`(판매처 운임까지 확인, 일정당 +1회).

## 실제 조회 전에 필요한 것

1. 이 폴더에 `.env.local` 파일을 만들고 `SERPAPI_API_KEY=...` 한 줄을 넣습니다.
2. `node collect.mjs`로 예상 조회 횟수를 확인합니다. 현재 설정은 일정 32개, 예상 116회입니다.
3. 처음에는 `node collect.mjs --live --cities fukuoka --max-calls 15`처럼 한 도시만 돌려 가격을 확인합니다.

## 수집 규칙

- 조건: 인천 출발 직항, 성인 2명, 객실 1개. 단거리 7개 도시는 3박 일정 4개, 파리·LA는 7박 일정 2개.
- 가격을 받지 못한 항목은 비워 두고, 화면은 그 도시의 전체 예산을 계산하지 않습니다.
- 완료된 일정이 절반 미만이면 기존 `snapshot.json`을 덮어쓰지 않고 `snapshot.failed.json`에 따로 저장합니다.
- 조회 상한(`--max-calls`)에 닿거나 인증·한도 오류가 나면 남은 일정을 건너뜁니다.

## 숙소 선택 기준

`lib/config.mjs`의 `HOTEL_RULES`에서 바꿀 수 있습니다.

- 인정하는 예약처: Agoda, Booking.com, Expedia, Hotels.com, Trip.com. 비교사이트 요금은 쓰지 않습니다.
- 숙소명·객실명에 호스텔, 캡슐, 도미토리 등이 있으면 제외합니다.
- 위치 확인 후보가 없는 도시(도쿄·다낭·나트랑·방콕·파리·LA)는 권역 검색 결과 중 3성급 이상, 구글 평점 4.0 이상, 리뷰 100개 이상인 곳만 상세 조회하고, 객실명이 확인된 요금만 씁니다.
- 기준을 통과한 숙소가 없으면 그 일정의 숙박은 비워 둡니다.

## 아직 안 된 것

- 2026-11-18에 실제 조회로 일정 32개를 한 번 수집했습니다(120회). 숙소 등급·평점 기준은 그 뒤에 추가해서 실제 응답으로는 아직 확인하지 못했습니다.
- 수집한 가격을 예약처 화면과 대조하지 않았습니다.
- 주 1회 자동 실행과 자동 게시 설정이 없습니다.
- 호스팅 위치가 정해지지 않았습니다.
- 예약 링크는 일반 링크라 제휴 수수료가 없습니다.
- 현지 경비 단가는 기존 사이트의 계획용 추정값이며 출처 있는 실측 자료가 아닙니다.
